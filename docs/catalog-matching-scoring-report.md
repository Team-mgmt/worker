# 도서 DB 매칭 및 점수 개선 보고서

작성일: 2026-08-14

## 목적

이 문서는 관리자 서가 분석에서 OCR 결과를 RDS의 도서 및 소장정보와
매칭하는 현재 방법, 핵심 제목 정규화와 문자 n-gram TF-IDF를 도입한 이유,
그리고 화면에 표시되는 점수와 실제 정답의 차이를 기록한다.

API 응답 및 S3 `result.json` 형식은 변경하지 않았다. 이 변경은 후보 생성과
재정렬 품질을 개선하며, 임계값을 임의로 낮춰 자동 확정 건수를 늘리지 않는다.

## 기존 문제

기존 제목 비교는 제목 전체에 대한 문자열 유사도의 영향을 크게 받았다.
따라서 서로 다른 책도 같은 저자와 일반적인 서지 문구를 공유하면 점수가
비슷해질 수 있었다.

관찰 사례는 다음과 같다.

- `환한 숨 : 조해진 소설집`과 `완벽한 생애 : 조해진 소설`이 `조해진`,
  `소설/소설집`을 공유하여 각각 77.1과 70.6처럼 가까운 점수를 받았다.
- `시간의 계단 : 주영하 장편소설`, `콩가루 수사단 : 주영하 장편소설`,
  `완벽한 행운 : 주영하 장편소설`은 `주영하 장편소설` 때문에 후보 간
  변별력이 낮았다.
- 청구기호와 제목이 부족한 OCR은 선택 도서관의 임의 후보 최대 1,500건과
  비교되어 `코케인`에 `노인`, `수인기`, `부케북` 같은 무관한 후보를
  표시할 수 있었다.
- `코케인 = Cocaine : 진연주 장편소설`처럼 병렬 표제가 있는 제목은 OCR의
  `코케인`과 비교할 때 불필요한 영문 표제가 점수를 희석할 수 있었다.

## 현재 후보 생성 순서

1. OCR 청구기호를 정규화한다.
2. `LibraryHolding.normalizedCallNumber`의 정확 일치 항목을 먼저 조회한다.
3. 정확 일치가 없으면 KDC와 도서기호 접두어를 사용해 후보를 제한한다.
4. 청구기호가 없으면 핵심 제목으로 SQL 후보를 제한한다.
5. 제한된 후보만 Python에서 점수화하고 상위 3개의 중복 없는 후보를 반환한다.

정확한 청구기호 조회는 기존 인덱스를 사용하므로 전체 12만 건을 Python에서
비교하지 않는다. 제목도 청구기호도 없는 경우 임의 후보를 만들지 않는다.

## 핵심 제목 정규화

제목과 저자에는 NFKC 및 공백 정규화를 적용한다. 이후 작품 식별에 불필요한
다음 표현을 제거한다.

- `장편소설`, `연작소설`, `청소년소설`, `소설집`
- `시집`, `에세이`, `대활자본`, `수상작`
- `지음`, `글`, `글·그림`, `옮김`
- 별도 저자 필드에서 확인된 저자명
- `:` 또는 `：` 뒤의 부제 및 책임표시
- `=` 또는 `＝` 뒤의 병렬 표제

예시는 다음과 같다.

```text
환한 숨 : 조해진 소설집                 -> 환한 숨
시간의 계단 : 주영하 장편소설           -> 시간의 계단
코케인 = Cocaine : 진연주 장편소설      -> 코케인
```

`=` 왼쪽을 주표제로 사용하는 것은 현재 정보나루/RDS 제목 형식을 전제로 한
MVP 규칙이다. 이후 다른 데이터 공급원에서 표제 형식이 달라지면 별칭 배열을
별도로 보존하여 양쪽 표제를 모두 검색 가능하게 확장해야 한다.

## 문자 n-gram TF-IDF 코사인 재정렬

정규화한 핵심 제목에서 공백을 제거한 뒤 문자 2-gram과 3-gram을 생성한다.
길이가 1자인 제목만 1-gram을 사용한다. 후보 집합 안에서 IDF를 계산하고,
OCR 핵심 제목과 각 DB 핵심 제목의 TF-IDF 코사인 유사도를 계산한다.

문자 n-gram을 사용한 이유는 다음과 같다.

- 한국어 형태소 분석 모델 없이 동작한다.
- OCR 공백 오류에 비교적 강하다.
- 한두 글자 인식 오류에도 일부 n-gram이 남는다.
- 같은 저자나 `장편소설` 같은 공통 문구보다 작품 고유 문자열을 강조한다.
- 외부 임베딩 모델을 추가하지 않아 CPU 메모리와 배포 복잡도가 작다.

현재 제목 점수는 다음과 같다.

```text
title_score = TF-IDF cosine * 70 + compact-title RapidFuzz ratio * 0.30
```

코사인은 0~1, RapidFuzz는 0~100이므로 최종 제목 점수는 0~100 범위다.
RapidFuzz를 함께 유지하여 매우 짧은 제목이나 후보가 적은 경우의 불안정을
보완한다.

## 종합 점수

내부적으로 제목, 저자, KDC, 도서기호 점수를 별도로 계산한다.

```text
bibliographic_score = title_score * 0.8 + author_score * 0.2
call_number_score   = KDC_score * 0.55 + book_code_score * 0.45
```

신뢰 가능한 KDC와 도서기호가 모두 있으면 청구기호 증거의 비중을 높이고,
KDC만 있으면 제목·저자 증거의 비중을 높인다. OCR 제목이 없으면 청구기호
중심 점수를 사용하지만 자동 확정은 최종 판정 조건을 다시 통과해야 한다.

## 점수와 정답은 같지 않다

화면의 점수는 후보가 정답일 확률로 보정된 값이 아니다. 현재 가중치로 계산한
후보 순위용 휴리스틱 점수다. 따라서 80점이 정확도 80%를 의미하지 않는다.

현재 관리자 판정의 주요 보호 조건은 다음과 같다.

- 후보가 없지만 OCR 증거가 있으면 `검수 필요`
- Top-1 점수가 75 미만이면 자동 확정하지 않음
- Top-1이 85 미만이면서 Top-2와의 점수 차이가 10 미만이면 `검수 필요`
- 충분히 신뢰되는 후보만 서가의 대표 KDC 추정에 사용
- 대표 KDC 범위와 다른 책은 별도의 오배열 판정 대상으로 처리

따라서 `환한 숨`의 Top-1이 실제 정답이어도 점수 차이가 작으면 검수 필요가
될 수 있다. 반대로 높은 점수라도 GT와 다른 책이면 잘못 확정한 오매칭이다.
임계값은 성공 사례 한 장이 아니라 GT 기준으로 조정해야 한다.

## 구현 및 회귀 테스트

관련 구현:

- `worker/services/matching_service.py`
- `worker/services/inference_service.py`
- `tests/test_matching_service.py`

회귀 테스트는 다음을 고정한다.

- 한글 및 호환 자모 청구기호 보존
- 정확한 정규화 청구기호 우선 조회
- 저자명과 일반 서지 문구 제거
- `=` 병렬 표제에서 주표제 선택
- 같은 저자의 서로 다른 작품을 n-gram으로 분리
- `시간의 계단`이 같은 저자의 다른 후보보다 충분한 점수 차이로 Top-1
- 제목만 있을 때 임의 카탈로그 1,500건을 비교하지 않음

구현 커밋:

- `367deaf`: `=` 병렬 표제 정규화 및 원격 관리자 로그

## 아직 필요한 평가

현재 변경은 단위 테스트를 통과했지만 실제 정확도 향상을 입증하는 GT 평가는
아직 완료되지 않았다. 노원중앙과 도봉아이나라를 분리하여 다음을 측정한다.

- DB matching Top-1/Top-3 accuracy
- 잘못 자동 확정한 오매칭률
- 정답 후보의 평균 순위와 MRR
- Top-1 점수 및 Top-1/Top-2 margin 분포
- 청구기호 전체/KDC/도서기호 exact accuracy
- 제목 exact 및 normalized accuracy
- OCR 난이도별 정확도와 지연시간

기존 S3 `result.json`에 GT 정답 holding ID를 연결한 뒤 이전 점수식과 현재
점수식을 같은 결과에 재생하는 오프라인 평가가 다음 단계다.
