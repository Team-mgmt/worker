# DB 후보 0건 KDC fallback

## 배경

노원중앙도서관 평가 실행의 33번 책은 실제로 `첫눈이 내려 : 진희
장편소설`(`813.6 진98ㅊ`)이지만 OCR은 제목을 `청눈이 내R`, 청구기호를
`813.6 98ㅊ`로 인식했다. 기존 운영 후보 조회는 숫자가 포함된 도서기호를
신뢰하고 첫 글자를 SQL 접두어로 사용했다.

```text
OCR 도서기호: 98ㅊ  -> bookCode LIKE '9%'
DB 도서기호:  진98ㅊ -> 조건 불일치
```

그 결과 후보군이 0권이 되어 RapidFuzz와 문자 n-gram TF-IDF가 실행될
비교 대상 자체가 없었다. 이는 재정렬(ranking) 실패가 아니라 후보 검색
(retrieval) 실패다.

## 변경한 검색 순서

1. 기존과 같이 정규화 청구기호 완전일치를 먼저 조회한다.
2. 완전일치가 없으면 KDC 접두어와 OCR 도서기호 첫 글자로 제한한다.
3. 2번 결과가 **0건이고**, 숫자를 포함한 도서기호 제한을 사용했다면 한 번만
   fallback을 수행한다.
4. fallback은 OCR의 정확한 KDC(`813.6%`)는 유지하고 도서기호 접두어 조건만
   제거한다.
5. 반환된 후보를 기존 TF-IDF·RapidFuzz·저자·청구기호 결합 점수로
   재정렬한다.

정상 요청의 SQL 수와 속도는 변하지 않는다. 후보 0건인 경우에만 추가 쿼리가
한 번 실행되며 최대 1,500건 제한을 유지한다.

## 안전장치

완화 조회로 얻은 후보의 `match_method`에는 `_relaxed`를 붙인다. 점수가 자동
확정 임계값을 넘더라도 운영 판정은 `needs_review`로 유지한다. 따라서 후보
누락은 복구하되, 넓어진 후보군의 잘못된 1위를 정상 도서로 자동 확정하지
않는다.

로그 예시는 다음과 같다.

```text
[matching] relaxed candidate fallback order=33 class='813.6' rows=...
```

## 평가 방법

변경 전후 동일 이미지와 GT를 사용해 다음을 비교한다.

- 후보군 누락 수
- DB Top-1 / Top-3
- 자동 확정 수와 오확정률
- fallback 발생 건수와 추가 지연시간

33번 책은 변경 전 `후보 없음`이었다. 변경 후 정답이 후보군과 Top-3에
포함되는지 확인하되, 자동 확정이 아니라 검수 필요로 표시되는지도 함께
검증한다.
